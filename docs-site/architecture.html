Architecture

Operator-facing overview of the Discord audio path, Gemini Live session lifecycle, plugin boundary, and loopback sidecar. Review the open issues linked below before deploying the bridge or exposing any local integration.

status
Current capability boundary. Core voice operation is under active development. Mutating sidecar routes remain unavailable under Issue #5; frame delivery remains blocked under Issue #9; and /notes exposes sensitive transcript/note data without authentication under Issue #4.

Audio path

Discord voice channel
    ↓ discord-ext-voice-recv decode
48 kHz stereo PCM16
    ↓ speech-energy and speaker filters
16 kHz mono PCM16
    ↓ Gemini Live realtime audio over WSS
Gemini Live session
    ↓ model audio output
24 kHz mono PCM16
    ↓ playback conversion
48 kHz stereo PCM16
    ↓ discord.AudioSource
Discord voice playback

Discord input is downsampled to 16 kHz mono before it is sent to Gemini. Gemini output is treated as 24 kHz mono and converted to Discord's 48 kHz stereo playback format. Do not rely on fixed latency, reconnect timing, or handshake-attempt counts; validate those properties against the exact deployed revision and environment.

Lifecycle

  1. A user starts a session through the Discord slash command or the configured Hermes tool.
  2. The plugin resolves the Discord adapter, guild, channel, and target speaker. Do not rely on an embedded account fallback; see Issue #16.
  3. The bridge connects to Discord voice, installs the PCM receive sink and playback source, and opens the Gemini Live WebSocket.
  4. Input audio is filtered and queued for Gemini; output audio is converted and queued for Discord playback.
  5. A watchdog observes connection state, target-user presence, idle prompting, and auto-leave conditions.
  6. A leave request, disconnect, target-user departure, or unrecoverable session failure stops the bridge and releases resources.

Sidecar /stop is intended to request the same shutdown but must be treated as unavailable until the authentication path and its clients are fixed and validated under Issue #5.

Loopback sidecar

The sidecar binds to:

127.0.0.1:${DISCORD_VOICE_LIVE_PORT:-18943}

Read-only health is available at GET /health. GET /notes?limit=N returns recent transcript/note events and backing-path metadata without authentication. Keep the service on loopback and do not proxy it to another host, browser, shared network, or tunnel.

The mutating routes /stop, /say, /frame, and /notify are intended to require X-API-Secret, but current main fails in the secret-comparison path. Built-in frame and notification clients also do not consistently attach the required header. Treat these routes as unavailable until exact-head server-to-client tests pass.

Key configuration

See Environment variables for the complete operator-facing list. Common values include:

DISCORD_BOT_TOKEN=***
GEMINI_API_KEY=***
GEMINI_MODEL=gemini-3.1-flash-live-preview
DISCORD_VOICE_LIVE_VOICE=Kore
DISCORD_VOICE_LIVE_PORT=18943
DISCORD_VOICE_LIVE_ALLOWED_SPEAKERS=
DISCORD_VOICE_LIVE_OUTPUT_PREROLL_MS=320
GEMINI_AUDIO_STREAM_IDLE_END_SECONDS=0.25

Keep secrets out of logs, issue bodies, review comments, screenshots, generated documentation, and shell history. Custom HERMES_HOME currently does not relocate every state/helper path; review the linked path issues before using a non-default root.
