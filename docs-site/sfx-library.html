SFX library — multi-slot UI sound effects

The bridge can play small slot-based sound effects into an active voice session. Each slot resolves a WAV file, converts supported input to 24 kHz mono PCM16, and fires on a specific bridge event.

The four slots

SlotTriggered byTypical role
tool_initFirst tool call of a session, once per sessionWork-start cue
errorUncaught exception in _run_local_toolError cue
notificationSuccessful local_notify deliveryMessage cue
transitionSession start after vc.play() succeedsConnection cue

The tool_init slot uses a one-shot guard so it does not replay for every tool call in the same session.

File layout and current path boundary

The runtime default is ~/.hermes/voice-users/sfx/:

~/.hermes/voice-users/sfx/
├── tool_init.wav
├── error.wav
├── notification.wav
└── transition.wav

On current main, this location is not derived from HERMES_HOME. The installer copies bundled files under $HOME/.hermes/voice-users/sfx, while the runtime independently uses the same home-relative default unless DISCORD_VOICE_LIVE_SFX_DIR is set.

For a custom Hermes root, set DISCORD_VOICE_LIVE_SFX_DIR="$HERMES_HOME/voice-users/sfx" explicitly and place approved WAV files there. Do not assume the installer populates that override. Path unification and migration behavior are tracked in Issue #18.

Media-rights boundary: the repository includes WAV files whose provenance is recorded, but redistribution permission has not been verified. Use your own explicitly licensed files or disable SFX while Issue #12 remains open. The repository software-license decision in Issue #7 does not establish rights to third-party audio.

Environment variables

Per-slot file override:

DISCORD_VOICE_LIVE_SFX_TOOL_INIT=/path/to/custom_chime.wav
DISCORD_VOICE_LIVE_SFX_ERROR=/path/to/custom_beep.wav
DISCORD_VOICE_LIVE_SFX_NOTIFICATION=/path/to/custom_ping.wav
DISCORD_VOICE_LIVE_SFX_TRANSITION=/path/to/custom_pop.wav

Per-slot volume is clamped by the runtime to 0.0 through 1.5, where 1.0 means no scaling:

DISCORD_VOICE_LIVE_SFX_TOOL_INIT_VOLUME=0.55
DISCORD_VOICE_LIVE_SFX_ERROR_VOLUME=0.45
DISCORD_VOICE_LIVE_SFX_NOTIFICATION_VOLUME=0.50
DISCORD_VOICE_LIVE_SFX_TRANSITION_VOLUME=0.60

Global enable:

DISCORD_VOICE_LIVE_SFX_ENABLED=true

Set this to false to prevent bundled or locally configured SFX from loading or playing.

Global runtime directory override:

DISCORD_VOICE_LIVE_SFX_DIR=/custom/sfx/dir

This override is read by sfx.py. Current install.sh still copies bundled files to $HOME/.hermes/voice-users/sfx.

local_sfx_test tool

The tool can play a configured slot in the active voice session or report slot configuration:

{"slot": "notification"}
{"action": "list"}

A list result reports each slot's resolved path, existence, volume, and cached byte count. With no active voice source, playback returns {"status": "no_active_source"}. Missing or unsupported files return a controlled no-SFX result rather than failing the bridge.

Adding or replacing a slot

  1. Place an explicitly licensed WAV in the configured SFX directory, or set the matching per-slot environment variable.
  2. For a new slot name, add it to DEFAULT_SFX_PATHS and DEFAULT_SFX_VOLUMES in reviewed runtime code.
  3. Call play_sfx("<slot>") from the reviewed bridge event.
  4. Add the slot to the local_sfx_test declaration and runner behavior.
  5. Restart the Hermes gateway after code or media changes.

Adding or replacing repository media is an asset- and licensing-sensitive change. Do not infer third-party media rights from the eventual repository software license.

Cache invalidation

The first successful load of a slot is cached in memory. Replacing a WAV at the same path does not replace the active cached bytes. Restart the Hermes gateway after replacing a file. There is no public cache-invalidation tool.
